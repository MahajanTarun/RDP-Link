# Development

## Design principles

1. **Ultra-light, ultra-fast** — RDP Link is a thin launcher around FreeRDP.
   The connect path never blocks: no network probes, no dialogs; bridges
   spawn in parallel with the client process.
2. **Stdlib only** — no third-party runtime dependencies. Tk for UI, system
   `ssh`/`scp` for deployment, `ffmpeg` + FreeRDP as external engines.
3. **Fail loudly, recover gracefully** — every bridge/client stderr lands in
   the session log; the receiver handshake turns silent failures into
   readable status lines.

## Layout

```
rdp_manager/            the package
├── paths.py            platform paths, resource lookup
├── exe.py              FreeRDP / ffmpeg discovery
├── profiles.py         store + schema migration (v1→v4)
├── secrets.py          Keychain / secret-tool / file + hex scheme + askpass
├── permissions.py      macOS TCC probing (no-op on Linux)
├── bridges.py          camera/mic bridges, receiver handshake, health loop
├── connection.py       FreeRDP arg builder, controller, headless mode
├── deploy.py           zero-setup receiver install over system ssh
├── logutil.py          per-session logs (last 10 kept)
└── ui/
    ├── app.py          main window (thin launcher)
    ├── editor.py       profile editor (devices/sharing/password/host setup)
    └── dialogs.py      password prompt
receiver/               host-side scripts (camera/mic receivers)
ubuntu_rdp_manager.py   entry point (GUI or CLI)
tools/gen_icon.py       icon generator (pure Python)
tests/                  pytest suite (no GUI required)
```

## Ports

| Port | Protocol | Purpose |
|---|---|---|
| 7272/udp | MPEG-TS | camera video client → host |
| 7273/udp | MPEG-TS | microphone audio client → host |
| 7274/udp | `RDPCTL1 PING/PONG` | camera receiver handshake |
| 7275/udp | `RDPCTL1 PING/PONG` | mic receiver handshake |

`PONG role=<camera|mic> data=<open|closed>` — `data=open` means the data
receiver's socket is bound (the responder can't bind it again), so the app
can distinguish "script alive" from "stream actually being received".

## Tests

```sh
python3 -m pytest            # 23 tests: profiles, args, secrets, handshake, deploy
```

The handshake tests spin real UDP responders (same protocol as the shell
scripts) on loopback; the Keychain tests exercise the real macOS Keychain
with throwaway accounts (skipped on Linux).

## Building

- macOS: `./build-app.sh` (PyInstaller windowed "RDP Link.app" + plist extras +
  ad-hoc re-sign; `--no-open` to skip launch)
- Linux: `./build-linux.sh` (PyInstaller onefile → `dist/rdp-link`)

Both exclude `pytest`/`unittest`/`pydoc_data`/`test` from the bundle to
keep it small. The icon is generated by `tools/gen_icon.py` (pure Python,
no PIL) and committed under `assets/`.

## Release checklist

1. `python3 -m pytest` green
2. `python3 -m pyflakes rdp_manager ubuntu_rdp_manager.py` clean
3. Build both targets; smoke-test GUI launch + CLI `--list` / `--connect`
4. Bump `__version__` in `rdp_manager/__init__.py` and `pyproject.toml`
5. Update README/docs if behaviour changed
6. `git tag vX.Y.Z`
